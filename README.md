# 本地数字素材目录

管理数字素材的目录与标签信息。面向本地单机使用，采用 Python 3 标准库与 SQLite，无需安装第三方依赖。

当前实现七个操作：素材登记（`add`）、按标签精确查询（`query`）、导出完整目录（`export`）、按路径查看单条记录（`show`）、替换、追加或移除标签（`retag`）、修改已登记素材的类型（`retype`）与统计全部已用标签（`tags`）。使用过程中源文件保持只读，不扫描其他目录，也不解码素材内容。

## 用法

全局必填选项 `--db` 指定 SQLite 数据库文件；文件不存在时自动创建（不自动创建缺失的父目录）。

```sh
# 登记素材：一个文件路径、必填 --type、至少一个可重复的 --tag
python -m asset_catalog --db catalog.sqlite add demo.png --type image --tag demo

# 成功输出（退出码 0）：
# {"path": "/abs/path/demo.png", "type": "image", "tags": ["demo"]}

# 按完整标签查询（区分大小写，不做子串匹配）
python -m asset_catalog --db catalog.sqlite query --tag demo
# [{"path": "/abs/path/demo.png", "type": "image", "tags": ["demo"]}]
# 无结果时输出 []

# --tag 可重复传入：默认（--tag-mode all）素材需同时具备全部不同标签才入选；
# 重复条件等同于只传一次，条件顺序不影响结果，单个 --tag 时语义不变。
python -m asset_catalog --db catalog.sqlite query --tag demo --tag ui

# --tag-mode any：素材只要具备任一标签即入选，每个素材仍只出现一次；
# 不传 --tag-mode 或传 all 时保持交集语义。--tag-mode 只接受小写 all 或 any。
python -m asset_catalog --db catalog.sqlite query --tag-mode any --tag demo --tag ui

# 查询时可选再按素材类型筛选：去除首尾空白后与登记类型完整匹配（区分大小写）
python -m asset_catalog --db catalog.sqlite query --tag demo --tag ui --type image
# any 与 --type 一起使用时，素材既要命中任一标签，也要匹配指定类型
python -m asset_catalog --db catalog.sqlite query --tag-mode any --tag demo --tag ui --type image
# 不传 --type 时查询范围、输出与排序均与只按标签查询一致

# 查询时可选再排除具备指定标签的素材（--exclude-tag 可重复传入）：
# 先按 --tag-mode（all/any）与可选 --type 确定范围，再剔除具备任一排除标签的素材
python -m asset_catalog --db catalog.sqlite query --tag-mode any --tag demo --tag ui --exclude-tag archived
# 同一标签同时用作命中与排除条件时仍执行排除；不存在的排除标签不影响结果
# 不传 --exclude-tag 时查询行为与之前一致

# 查询时可选再按当前文件状态筛选：只返回状态匹配的素材，输出字段不变
python -m asset_catalog --db catalog.sqlite query --tag demo --file-status missing
# 与 --check-files 同用时，入选记录追加与筛选值一致的 file_status
python -m asset_catalog --db catalog.sqlite query --tag demo --file-status missing --check-files
# 不传 --file-status 时不按状态筛选，查询行为与之前一致

# 导出完整目录：无筛选参数，标准输出仅为一个 JSON 数组
python -m asset_catalog --db catalog.sqlite export
# [{"path": "/abs/path/demo.png", "type": "image", "tags": ["demo"]}]
# 每条记录仅含 path、type、tags；按首次登记顺序各出现一次，空目录输出 []

# 可选追加 --check-files：无需指定标签即可查看整个目录的文件状态，
# 每条记录在原有字段之外追加 file_status（状态定义与 query 一致：
# present / missing / not_file），缺失文件或已变成目录的记录也保留
python -m asset_catalog --db catalog.sqlite export --check-files
# [{"path": "/abs/path/demo.png", "type": "image", "tags": ["demo"], "file_status": "present"}]
# 任一记录状态无法判断时整次导出失败：退出码 2、标准输出为空、
# 标准错误说明无法确定文件状态并包含相关路径，不输出部分 JSON

# 统计全部已用标签：无参数，标准输出仅为一行 JSON 数组
python -m asset_catalog --db catalog.sqlite tags
# [{"tag": "UI", "asset_count": 1}, {"tag": "demo", "asset_count": 2}, {"tag": "ui", "asset_count": 1}]
# 每项仅含 tag 与 asset_count；标签不重复，按 Unicode 码点字典序升序，空目录输出 []

# 只统计指定类型素材的标签：--type 去除首尾空白后完整匹配（区分大小写）
python -m asset_catalog --db catalog.sqlite tags --type image
# [{"tag": "UI", "asset_count": 1}, {"tag": "demo", "asset_count": 2}, {"tag": "ui", "asset_count": 1}]
# 无匹配类型输出 []

# 只列出名称以指定文本开头的已用标签：--prefix 先去除首尾空白，
# 再与保存的标签文本逐字符比较（区分大小写、只匹配开头、保留中间空白与中文）。
# 例如 A（image: ui、ui.button、UI）、B（image: ui.button）、
# C（audio: ui.button、audio）三条记录：
python -m asset_catalog --db catalog.sqlite tags --prefix ui
# [{"tag": "ui", "asset_count": 1}, {"tag": "ui.button", "asset_count": 3}]
# 与 --type 同用时先限定类型范围再保留前缀标签：
python -m asset_catalog --db catalog.sqlite tags --prefix ui --type image
# [{"tag": "ui", "asset_count": 1}, {"tag": "ui.button", "asset_count": 2}]
# UI 不入选；%、_ 与反斜线均为普通字符；无匹配标签输出 []

# 按路径查看单条记录：只接收一个素材路径，无需标签
python -m asset_catalog --db catalog.sqlite show ./demo.png
# 成功输出（退出码 0，标准错误为空，标准输出仅一行）：
# {"path": "/abs/path/demo.png", "type": "image", "tags": ["demo"]}
# 路径按 add 规则解析；默认不读取素材内容、不检查当前文件状态，
# 源文件已删除或原登记路径变成目录时通过原路径仍返回该记录；
# 未登记时退出码 2，标准错误说明素材未登记并包含规范绝对路径

# 可选追加 --check-files：先定位登记记录，再检查记录保存路径当前的文件状态，
# 在原字段之外追加 file_status（状态定义与 query 一致：present / missing /
# not_file），退出码 0、标准错误为空、标准输出仅一行
python -m asset_catalog --db catalog.sqlite show ./demo.png --check-files
# {"path": "/abs/path/demo.png", "type": "image", "tags": ["demo"], "file_status": "present"}
# 源文件已删除或为断开的链接、中间组件不是目录时为 missing，
# 目录等非普通文件为 not_file，符号链接按目标判断
# 未登记路径无论是否存在都退出码 2、标准输出为空；状态无法读取（权限或其他
# 系统错误）时退出码 2、标准输出为空，标准错误指出状态读取失败及相关路径

# 替换一条已登记素材的全部标签：一个素材路径、至少一个可重复的 --tag
python -m asset_catalog --db catalog.sqlite retag demo.png --tag project --tag ui
# 成功输出（退出码 0）替换后的完整记录：
# {"path": "/abs/path/demo.png", "type": "image", "tags": ["project", "ui"]}

# 追加标签：--append 保留旧标签，把新标签接在末尾（已存在的标签不移动、不重复）
python -m asset_catalog --db catalog.sqlite retag demo.png --append --tag archive
# 成功输出（退出码 0）追加后的完整记录：
# {"path": "/abs/path/demo.png", "type": "image", "tags": ["project", "ui", "archive"]}

# 移除标签：--remove 从旧标签中移除指定标签，其余标签保持原顺序
python -m asset_catalog --db catalog.sqlite retag demo.png --remove --tag ui
# 成功输出（退出码 0）移除后的完整记录：
# {"path": "/abs/path/demo.png", "type": "image", "tags": ["project", "archive"]}

# 修改一条已登记素材的类型：一个素材路径、必填 --type
python -m asset_catalog --db catalog.sqlite retype demo.png --type texture
# 成功输出（退出码 0）修改后的完整记录：
# {"path": "/abs/path/demo.png", "type": "texture", "tags": ["project", "archive"]}
```

## 规则

- 文件路径会解析为规范绝对路径（相对路径、`.`、`..` 及符号链接均会解析），同一规范路径重复登记将被拒绝。
- 目录数据库不能作为素材登记到自身：素材路径与 `--db` 数据库路径的规范绝对路径相同时拒绝登记（退出码 2，标准错误指出冲突的规范路径），数据库文件与既有记录保持不变；已有空文件不会因此被初始化，非 SQLite 或不兼容 SQLite 文件也保持原内容。路径不同的其他 SQLite 文件不受此限制，仍可正常登记。
- 类型与标签去除首尾空白后保存；标签按首次出现顺序去重，大小写保留。
- 查询结果按首次登记顺序排列；源文件事后被删除不影响已保存的记录。
- 查询 `--tag` 可重复传入，每个标签分别去除首尾空白，重复条件等同于只传一次，条件顺序不影响结果。`--tag-mode` 为 `all`（默认，不传时同此）时素材需同时具备全部不同标签才入选；为 `any` 时只要具备任一标签即入选，命中多个条件也只返回一次。两种方式都区分大小写并完整匹配，无匹配时输出 `[]`。
- `--tag-mode` 只接受小写 `all` 或 `any`：缺少值、为空、含首尾空白、大小写不符或取其他值时按参数错误处理（退出码 2、标准输出为空、标准错误指出该选项）；任一 `--tag` 为空或只有空白时同样拒绝整次查询（即使 `any` 的其他标签有效），错误原因指向 `--tag`。
- 查询可通过 `--type` 在标签命中范围内再按类型完整匹配筛选；与 `any` 一起使用时，素材既要命中任一标签，也要匹配指定类型；非空类型无匹配时输出 `[]`，`--type` 缺失值或去空白后为空按参数错误处理（退出码 2）。
- 查询可通过可重复的 `--exclude-tag` 在标签命中范围内排除素材：先按既有 `all`/`any` 语义及可选 `--type` 确定范围，再剔除具备任一排除标签的素材。排除标签逐个去除首尾空白，重复条件只生效一次，条件顺序不影响结果，按完整文本区分大小写匹配。不存在的排除标签不影响结果；同一标签同时用作命中条件与排除条件时仍执行排除，不报冲突错误。结果保持首次登记顺序，每条素材只出现一次，返回完整标签及原顺序，无匹配输出 `[]`。排除只作用于本次查询，不修改任何记录或源文件，也不读取素材内容。`--exclude-tag` 缺值、为空或仅有空白时整次按参数错误拒绝（退出码 2、标准输出为空、标准错误指出该选项、不含调用栈），即使其他条件有效也不返回部分结果，且不创建数据库；`--exclude-tag` 只属于 `query`，其他子命令收到它按同样规则拒绝。不传 `--exclude-tag` 时保持已有查询行为，旧数据库无需迁移。
- `--check-files` 只为最终入选记录追加 `file_status`（`present` / `missing` / `not_file`），任一入选记录状态无法读取时整次查询失败且不输出部分结果；未入选素材的文件状态不影响查询。不传该选项时不检查文件状态，源文件已删除仍可按登记标签入选。与 `--exclude-tag` 同用时被排除素材不检查文件状态，文件状态规则只作用于排除后的剩余范围。
- `--file-status` 只改变入选范围：先按既有标签交集或并集、可选 `--type` 及 `--exclude-tag` 排除确定候选，再筛选当前文件状态为指定值的素材。普通文件属于 `present`，路径不存在或中间组件不是目录属于 `missing`，目录等非普通文件属于 `not_file`；符号链接按目标判断，断链属于 `missing`。单独使用时仍输出仅含 `path`、`type`、`tags` 的 JSON 数组；与 `--check-files` 同用时入选记录追加与筛选值一致的 `file_status`。结果保持首次登记顺序、每条素材只出现一次、完整标签及其顺序不变，无匹配输出 `[]`。任一剩余候选因权限或其他系统错误无法判断状态时整次查询失败（退出码 2、标准输出为空、标准错误指出状态读取失败及相关路径），不输出部分结果；未命中标签、类型的素材与被 `--exclude-tag` 排除的素材不检查状态。该选项只接受小写 `present`、`missing`、`not_file`：缺值、为空、含首尾空白、大小写不符或取其他值时按参数错误处理（退出码 2、标准输出为空、标准错误指出 `--file-status`），不创建数据库。查询不保存状态、不改动记录和源文件。
- `export` 不接受标签、类型等任何筛选参数，导出全部登记记录；结果按首次登记顺序排列，每条素材仅出现一次且只含 `path`、`type`、`tags`（无 `file_status` 或内部编号），保留规范绝对路径、类型文本与完整标签顺序。
- `export --check-files` 在保持上述导出语义的前提下，为每条记录追加 `file_status`：普通文件为 `present`，路径不存在、断开的符号链接或中间组件不是目录为 `missing`，目录等非普通文件为 `not_file`，符号链接按目标判断，输出 `path` 仍保留登记值；状态定义与 `query --check-files` 完全一致。缺失文件或已变成目录的记录照常保留，空目录输出 `[]`。任一记录因权限或其他系统错误无法判断状态时整次导出失败（退出码 2、标准输出为空、标准错误说明无法确定文件状态并包含相关路径），不输出调用栈或部分 JSON。每次状态反映当次检查，不保存到数据库，不读取素材内容、不扫描目录，也不改写或补建源文件。不传该选项时输出与文件状态检查均保持原有行为，旧数据库无需迁移。
- 导出直接反映数据库中的登记记录：不读取素材内容、不检查登记路径当前的文件状态，源文件事后被删除或原路径变成目录都不会漏掉素材；导出不改动数据库与素材文件。
- `tags` 不接受素材路径、`--tag`、`--check-files` 等参数，统计数据库中当前保存的全部已用标签：每项仅含 `tag`（保存的标签文本，不改写）与 `asset_count`（具有该标签的已登记素材数，正整数）。统计按完整文本区分大小写（`ui` 与 `UI` 是两个标签），同一素材的同一标签只计一次，不同登记路径即使文件内容相同仍分别计数；没有素材使用的标签不输出零计数项。标签不重复，按标签文本的 Unicode 码点字典序升序排列，空目录输出 `[]`。`retag` 或 `retype` 的修改在下次统计中生效。统计只反映当前保存的元数据：不检查文件状态、不读取素材内容、不扫描目录，源文件已删除或原路径变成目录的素材仍参与统计；统计不改动数据库与素材文件，旧数据库无需迁移。
- `tags --type` 只统计指定类型素材的标签：类型值去除首尾空白后与登记类型完整匹配（区分大小写，`Image` 不匹配 `image`），接受任意非空文本，不根据扩展名推断；输出格式与排序规则与全目录统计一致，无匹配类型或空目录输出 `[]`。`--type` 缺值、为空或只有空白时按参数错误处理（退出码 2、标准输出为空、标准错误指出 `--type` 及原因），不创建数据库。不传 `--type` 时保留原有全目录统计。
- `tags --prefix` 只列出名称以指定文本开头的已用标签：前缀值先去除首尾空白，再与保存的标签文本逐字符比较——区分大小写（`UI` 不以 `ui` 开头），只匹配标签开头、不做中间子串匹配（`button` 匹配不到 `ui.button`），保留中间空白和中文；`%`、`_` 与反斜线均为普通字符，不做通配或转义。`asset_count` 仍表示具有该完整标签的已登记素材数，同一素材只计一次，不把共享前缀的不同标签合并；与 `--type` 同用时先在指定类型素材中统计，再保留满足前缀的标签（`tags --prefix ui --type image` 得 `ui` 计 1、`ui.button` 计 2）。输出仍是每项仅含 `tag` 与 `asset_count` 的单行 JSON 数组，保留标签原文，按 Unicode 码点字典序升序排列，无匹配前缀或空目录输出 `[]`。`--prefix` 缺值、为空或只有空白时按参数错误处理（退出码 2、标准输出为空、标准错误指出 `--prefix` 及原因、不含调用栈），不创建数据库；`--prefix` 只属于 `tags`，其他子命令收到它时同样按参数错误拒绝。统计不检查文件状态、不读取素材内容、不改动数据库与源文件；不传 `--prefix` 时保留 `tags` 的原有行为。
- `show` 只接收一个素材路径，除可选的 `--check-files` 外不接受标签或其他选项：素材路径按与 `add` 相同的规则解析为规范绝对路径定位记录，相对路径、`.`、`..` 及解析后指向同一登记路径的符号链接都定位同一记录。命中时退出码 0、标准错误为空，标准输出仅一行 JSON 对象，默认只含 `path`、`type`、`tags`，反映当前保存的类型与完整标签，标签顺序与登记（或最近一次 `retag`）顺序一致。
- `show` 默认只反映数据库中的登记记录：不读取素材内容、不检查登记路径当前的文件状态，源文件已删除或原登记路径变成目录时，通过原登记路径仍返回该记录；查看为只读操作，不改动数据库、记录与素材文件，已有记录的路径、类型、标签及首次登记顺序均不变。未登记时退出码 2，标准错误说明素材未登记并包含该路径解析后的规范绝对路径。
- `show --check-files` 在保持上述定位语义的前提下，于命中记录后再检查**记录保存路径**当前的文件状态，在原字段之外追加 `file_status`：普通文件为 `present`，路径不存在、断开的链接或中间组件不是目录为 `missing`，目录等非普通文件为 `not_file`，符号链接按目标判断；状态定义与 `query --check-files` 完全一致，且只检查这一条命中记录的保存路径，其他素材的文件状态不影响本次查看。先定位登记记录再检查状态：未登记路径无论文件是否存在都退出码 2、标准输出为空、标准错误说明素材未登记并包含规范路径，不返回其文件状态；因权限或其他系统错误无法判断命中记录的状态时退出码 2、标准输出为空、标准错误指出状态读取失败及相关路径，不输出调用栈或部分 JSON。每次结果反映查看时的当前状态，不保存状态、无需重新登记；查看不读取素材内容，也不改写源文件或数据库，不改变标签顺序与登记顺序。不传该选项时输出与文件状态检查均保持原有行为，旧数据库无需迁移。
- `show` 的素材路径缺失或为空字符串、缺少 `--db`、数据库路径为空字符串、传入不支持的参数：退出码 2，标准输出为空，标准错误指出对应参数及原因，不输出调用栈；参数错误不创建数据库。数据库文件不存在但父目录存在时，沿用空库创建规则初始化后报告素材未登记（带 `--check-files` 时同样先报未登记，不检查未登记路径）；父目录缺失时报错且不补建目录。数据库路径指向目录、数据库打不开、内容损坏、结构不兼容或记录读取失败时退出码 2、标准输出为空、标准错误说明具体原因，不输出部分记录。`show` 兼容现有数据库，无需迁移。
- `retag` 用新标签完整替换一条已登记素材的旧标签：素材路径按与 `add` 相同的规则解析为规范绝对路径定位记录，等价写法命中同一记录；新标签去除首尾空白、按首次出现顺序去重、保留大小写，重复提交相同的规范化标签与顺序仍成功。只替换标签：素材路径、类型、首次登记顺序与其他素材的记录保持不变，源文件内容保持只读；源文件已删除或变成目录仍可修改标签。不提供批量修改或清空全部标签的操作。结果持久保存，之后的 `query` 与 `export` 反映新标签，被移除的标签不再使该素材入选。
- `retag --append` 保留旧标签并追加新标签：新标签按输入顺序去除首尾空白、按首次出现顺序去重（区分大小写，`ui` 与 `UI` 是两个标签），原标签及其顺序保留，已存在的标签不移动，新标签接在末尾；重复追加同一批标签仍成功，标签不增加也不重排。两种模式都要求至少一个 `--tag`，成功输出均为仅含 `path`、`type`、`tags` 的完整 JSON 对象，`tags` 为追加或替换后的全部标签。`--append` 只属于 `retag`，其他命令收到它按参数错误拒绝。
- `retag --remove` 从旧标签中移除指定标签：待移除标签去除首尾空白、按首次出现顺序去重（重复条件只生效一次），按完整文本区分大小写匹配；未指定的标签保持原顺序，不存在的标签忽略，重复移除同一批标签仍成功。素材至少保留一个标签：若操作会移除全部标签，整次拒绝（退出码 2，标准错误说明不能移除全部标签），原记录与标签顺序完整保留。`--remove` 与 `--append` 互斥，同时指定按参数错误拒绝且不创建数据库；不传 `--remove` 时保留原替换和追加行为。成功输出为仅含 `path`、`type`、`tags` 的完整 JSON 对象，`tags` 为移除后的全部标签。`--remove` 只属于 `retag`，其他命令收到它按参数错误拒绝。
- `retag` 的素材路径缺失或为空、缺少 `--tag`、任一标签为空或只有空白、传入不支持的参数、目标未登记（标准错误含规范路径）、数据库无法打开或读写、损坏或结构不兼容时：退出码 2，标准输出为空，标准错误给出原因，不输出调用栈。参数错误不创建数据库；失败不新增素材、不改变已有记录，也不留下部分新标签。数据库文件不存在但父目录存在时按既有规则创建空库后报告目标未登记；父目录缺失时报错且不补建目录。
- `retype` 只修改一条已登记素材的类型：素材路径按与 `add` 相同的规则解析为规范绝对路径定位记录，等价写法命中同一记录；新类型去除首尾空白、保留大小写，接受任意非空文本，不根据扩展名猜测类型，提交与当前类型相同的规范化值仍成功且输出不变。只改类型：素材路径、完整标签及其顺序、首次登记顺序与其他素材的记录保持不变，源文件内容保持只读；源文件已删除或原路径变成目录仍可通过原登记路径改类型，操作不读取素材内容，也不创建、移动或改写源文件。结果持久保存，之后的 `query --type` 按新类型筛选，`export` 显示新类型。成功输出为仅含 `path`、`type`、`tags` 的完整 JSON 对象，反映修改后的完整记录。
- `retype` 的素材路径缺失或为空、`--type` 缺值或去除首尾空白后为空、传入不支持的参数、目标未登记（标准错误含规范路径）、数据库无法打开或读写、损坏或结构不兼容时：退出码 2，标准输出为空，标准错误给出原因，不输出调用栈。参数错误不创建数据库；失败不新增素材、不改变已有记录，也不留下部分修改。数据库文件不存在但父目录存在时按既有规则创建空库后报告目标未登记；父目录缺失时报错且不补建目录。
- 已存在但损坏或不属于本产品结构的数据库会报错，不会被覆盖、补表或重建；读取失败时不输出部分记录。判定是否已有业务内容时同时清点用户表与用户视图：视图可以独立返回常量而不依赖任何表，所以 SQLite 文件即使没有任何用户表，只要含一个或多个用户视图（含名为 `asset` 或 `asset_tag` 的视图），也按不属于本产品结构拒绝（退出码 2、标准输出为空、标准错误包含指定数据库路径、不含调用栈），文件字节与原视图定义、查询结果完全保留；视图数量和名称不改变结果。只有既无用户表也无用户视图的文件（父目录存在时路径尚不存在、已有零字节文件、`sqlite_master` 为空或仅含内部表 `sqlite_sequence` 的空 SQLite 库）才按空目录库初始化。
- `add` 的参数缺失、类型/标签为空、路径不存在或不是普通文件、重复登记、把目录数据库自身登记为素材、数据库无法打开或写入时：退出码 2，标准输出为空，标准错误给出原因，不输出调用栈。
- 缺少 `--db`、数据库路径为空、子命令传入不支持的参数、数据库路径指向目录、父目录缺失、数据库无法打开或读取、内容损坏或表结构不兼容时：退出码 2，标准输出为空，标准错误给出原因，不输出调用栈。
